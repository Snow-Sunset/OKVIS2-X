# 独立 BRISK 跟踪与滑窗后端

在线模式把图像跟踪与滑窗图处理分到两个执行路径。前端保留 BRISK，后端沿用原有
数据关联、初始化、三角化、滑窗优化、边缘化和回环应用。这样可先比较线程解耦带来的
变化，再评估 KLT、仅关键帧提取描述子等算法调整。

## 参考结构与所有权

[ORB-SLAM3 的 System](https://github.com/UZ-SLAMLab/ORB_SLAM3/blob/master/src/System.cc)
单独启动 LocalMapping 和 LoopClosing 线程；
[Tracking](https://github.com/UZ-SLAMLab/ORB_SLAM3/blob/master/src/Tracking.cc)
负责当前帧跟踪和关键帧决策。
[VINS-Fusion 的 Estimator](https://github.com/HKUST-Aerial-Robotics/VINS-Fusion/blob/master/vins_estimator/src/estimator/estimator.cpp)
用特征队列交给估计线程，并在优化后通过 `updateLatestStates()` 更新传播起点、重放
尚未处理的 IMU。这里借鉴上述职责划分，使用独立实现，保留 OKVIS 的 BRISK 和后端。

- 跟踪路径只读取不可变局部地图快照，估计当前帧位姿；地图点和相机外参在该次
  pose-only 优化中保持固定。速度和 IMU 偏置来自后端反馈及 IMU 传播。
- 后端拥有可修改的滑窗图。前端不读取 `Estimator`，不修改图中的状态、观测或地图点。
  在线后端在同一个后台线程顺序完成数据关联、局部优化、边缘化和快照发布；原有全局
  图优化线程继续处理独立全局图，并由后端在安全点导入结果。
- 前端向后端提交独立的图像特征副本。后端自行完成数据关联及优化，不把前端已融合
  的位姿再当作独立观测加入图，避免重复计算同一份图像和 IMU 信息。
- 已有的回环工作线程继续只生成候选，图修改由后端在安全点应用。

## 后端反馈与当前时刻

反馈将版本号、状态时间戳、位姿、速度、陀螺偏置、加速度偏置、相机外参和局部地图
作为同一份不可变快照发布。局部地图同时受半径和数量上限控制，不将不断增长的历史
地图直接交给逐帧匹配。快照从当前帧及其共视帧的观测构建，访问帧数不超过
`num_keyframes + num_loop_closure_frames + num_imu_frames`（至少一帧），每个地图点
最多复制三份 BRISK 描述子。

收到新的后端反馈后，前端从反馈的状态时间戳出发，使用对应偏置重放到当前图像时刻
的 IMU，再进行当前帧的视觉位姿估计。旧版本或时间倒退的反馈不可覆盖新的跟踪状态。
缺少覆盖该时间段的 IMU、尚未初始化或视觉约束不足时，必须报告相应状态，不能把旧
时刻的优化位姿伪装成当前帧结果。

## 候选帧与过载

前端根据跟踪重叠率、平移、转角或传感器时间间隔请求后端处理候选帧。最终是否为
图中关键帧仍由后端原有逻辑决定，前端请求不会作为强制关键帧先验传入后端。
跟踪重叠率按当前图像检测区域与内点覆盖区域计算，避免共视地图扩大时分母随历史点数
增长而持续触发请求。初始化阶段需要持续提供候选。

仅在后端空闲时接纳新候选，同一时刻最多有一个已接纳任务，包括尚未取走的任务或
正在处理的活动任务。后端忙时，当前候选保持未接纳，前端继续跟踪，后续新图像可重新
提议；不在活动优化后面积压旧图像，也不替换或删除已接纳任务。只有成功入队且跟踪
有效后才更新前端的候选帧门限起点。请求的最大时间间隔不保证后端处理间隔，实际
接纳频率取决于后端吞吐。原始图像入口另外保留两帧，入口满时替换旧图；跟踪线程
已取出的活动图像不受入口替换影响。`raw image drops` 与 `candidate rejected` 分别
统计这两种过载。

启用实时 LiDAR 配准时，若完整扫描的末点早于当前图像、跟踪有效且后端空闲且无
已接纳任务，前端可额外提交一个普通图像更新来及时消费该扫描。这类 `lidar-driven
updates` 不强制关键帧、不推进视觉关键帧门限，沿用后端空闲时才接纳的规则，
避免低关键帧频率让空闲后端仍然替换扫描。后端最终仍可按原有视觉/LiDAR策略选择关键帧。

跳过候选图像不等于跳过 IMU：后端保留相邻已接纳帧之间的完整 IMU 时间跨度；前端
保留从有效反馈锚点重新传播所需的 IMU。不能只按当前图像时刻裁剪缓存，导致延迟
反馈到来后失去重传播数据。在线独立路径的前端 IMU 重传播缓存和后端 IMU 输入队列
各有 5000 个样本的紧急上限；达到上限明确抛出过载异常，不静默替换旧 IMU。时间不递增的 IMU 会被拒绝并
记录错误。持续过载仍会降低后端图像覆盖率，线程拆分不保证任意倍率回放均无丢帧。

首次反馈到达前保留启动 IMU 区间，不能提前按图像时刻裁剪，否则延迟返回的初始化
状态会失去传播数据。后端重置以新版本的失效快照通知前端，旧版本地图不能恢复。

调用 `flushPendingUpdates()` 前必须先停止传感器输入。随后排空已接纳的后端任务，
等待局部优化及发布完成，再处理建图尾部和对齐反馈。若输入不足以完成已接纳任务，
必须明确报告失败，不能当作成功排空。
尚未接纳且缺少末尾 IMU 覆盖的图像会单独记录为退出时的未接纳图像，不计作成功后端更新。

## 配置

以下字段放在 `frontend_parameters`，省略时采用表中默认值。数值字段必须为正数，
浮点字段还必须有限。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `independent_tracking` | `true` | 在线非阻塞模式使用独立跟踪；`false` 使用原逐帧路径，便于对比 |
| `tracking_max_landmarks` | `2000` | 单份局部地图快照最多保留的地图点数量 |
| `tracking_map_radius` | `50.0` | 以反馈位置为中心的局部地图半径，米 |
| `tracking_max_keyframe_interval` | `0.25` | 请求后端候选的最大传感器时间间隔，秒 |
| `tracking_keyframe_translation` | `0.5` | 请求候选的平移门限，米 |
| `tracking_keyframe_rotation` | `0.15` | 请求候选的旋转门限，弧度 |

阻塞式离线输入保留原有同步处理路径，不使用在线跳帧策略。运行中不能随意切换处理
模式；进行架构对比应重新启动，并使用相同数据段、输入频率及配置。

## 输出与验证

当前帧跟踪结果与后端优化结果代表不同时间尺度。ROS 的 `okvis_frontend_odometry`
和 `okvis_frontend_path` 用于观察图像时刻的有效跟踪；前端丢失时不发布有效位姿。
原有优化输出用于观察图状态、建图和历史轨迹修正。前端输出不修改后端轨迹，也不
另发同名 TF。

回环或全局调整会改变反馈中的世界坐标，前端必须使用同一版本的状态和地图，避免
旧地图与新位姿混用。前端 path 保留当时发布的历史采样，不随回环重写已有点，因而
反馈校正后可能出现接续跳变；评估闭环后轨迹应使用后端优化输出。

本次按要求不编译，也不声称已通过运行或 bag 精度验证。后续应在相同数据段和
`ros2 bag play campus_train0 -r 3` 条件下，对比输入图像替换次数、跟踪有效率、前端
P95/P99 耗时、后端候选拒绝数、反馈延迟、闭环成功数及轨迹误差。检查重点还包括
反馈延迟期间的 IMU 完整性、退出时已接纳队列排空，以及模式切换的线程所有权。

在线日志每 100 帧报告累计输入丢图、候选拒绝、跟踪失效次数、当前匹配/内点数、
反馈版本、传感器时间反馈延迟，以及最近最多 256 帧前端处理耗时的 P95/P99。
耗时覆盖本次 IMU 拷贝、提取、匹配、前端输出和候选提交，不含等待未来 IMU 的时间。
已补充反馈/失效版本、IMU 重传播和四种相机几何的测试源码，尚未编译或执行。
