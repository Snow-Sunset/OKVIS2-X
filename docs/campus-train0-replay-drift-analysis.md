### 本轮保持匹配规则的开销优化

- `Frontend::matchToMap()` 按观测帧和相机缓存组合位姿，复用同一调用内不变的矩阵，
  不再对每个地标观测重复组合。缓存只在准备与第一轮匹配期间使用；
  后续初始位姿优化、闭环和下一帧重新计算，不跨可变图状态复用。
- 描述子候选直接在两轮匹配共同使用的容器中构造，并移动临时候选，
  去掉整幅候选 map 及 Eigen 观测矩阵的额外深拷贝。
- `ViGraph::getLandmark()` / `getLandmarks()` 以引用访问观测记录，
  对有序观测使用插入提示，并移动新建的观测 ID 集合，避免逐观测边对象和集合的重复复制。
  返回数据仍是独立快照，不从活动图移走观测。
- 新增 `2.01.1`–`2.01.6` 子计时：地标复制、描述子准备、初始地标匹配、
  初始位姿修正、未初始化地标匹配和恢复位姿优化。候选规模日志记录地标数、观测访问数
  与缓存相机位姿数，便于区分候选增多、匹配计算和恢复开销。

没有改变匹配候选集合、阈值、观测顺序、RANSAC 规则、优化迭代次数、滑窗、
局部建图参数或全局 PCD 密度。上述等价计算优化仍需构建及运行回归确认，
没有测得本轮实际加速比例，也没有新的轨迹精度结论。

### 本轮已写入的优化（未回放验证）

1. 为主估计器实时激光因子增加独立的 `RealtimeLidarMeasurementBuffer`，
   使用连续扫描数组保存数据，替代逐点 deque 的等待扫描存储。
   默认最多 16 幅等待扫描，另保留消费者正在读取的活动扫描；活动与等待扫描的
   **数组 capacity 载荷合计上限 64 MiB**，两项限制同时生效。
   该值不包含队列元数据、原始 ROS 输入、临时复制的一幅扫描或消费者工作集，
   不能当作整个 SLAM 进程的内存上限。
2. 生产者不再用最新输入反复覆盖唯一等待扫描。超限时优先替换最远未来的等待扫描，
   保留活动扫描和更靠近后端时刻的旧等待扫描；无法与活动扫描同时装入预算的输入被拒绝。
   消费者按当前图像时刻跳过过旧的完整扫描，保留最近一幅完整扫描和后继扫描已就绪前缀，
   不要求后端逐幅补算整个积压。批次内保持原始点和严格 `< image_time` 边界，
   连续前缀批量转移。逐点离线输入保留原有无损语义，不与完整扫描通路混用。
3. 轻量不可变跟踪反馈在完整图发布队列入队前交给前端。
   当前有界内存模式下完整图更新仍保留原有阻塞和保序规则；这避免满队列延迟本轮反馈，
   但不消除完整发布本身或下一轮后端仍可能受到的反压。
4. 新增 `4.1 Full publication queue wait` / `4.2 Full publication callback` 计时，
   以及 `Realtime LiDAR aligned input` 的队列、载荷、过旧扫描合并、超限替换和拒绝计数。
   激光去畸变失败日志补充扫描/IMU 数量与时间范围，便于区分空扫描与时间支持不足；
   该日志本身仍不是 IMU 丢失的证明。

新增可选 OKVIS YAML 参数位于 `estimator_parameters`，不属于 ROS `global_lidar_pcd` 参数：

```yaml

realtime_lidar_buffer_bytes: 67108864
```

合法范围分别为 1–64 幅和 1024–268435456 字节。旧配置缺省时也使用 16/64 MiB。
本轮没有降低全局地图密度、改变真实关键帧合并规则、修改局部建图缓存，
也没有启用优化器时间截断或修改迭代次数、滑窗大小。
已增加缓存边界、时间对齐、消费者合并、重复时间戳、内存限额、退出排空和逐点兼容的测试源码；
按“不编译”要求未执行 C++ 测试。静态检查通过不代表二倍速漂移已经解决。

## 此前分析的结论与证据边界

最新一倍速会话也发生真实跟踪失败，因此不能再把倍速作为充分解释或认定为唯一主因。
两种速率都观察到反馈滞后、实时 LiDAR 等待扫描替换，以及视觉约束退化。
全局 PCD 建图和显示存在额外资源开销，应优先隔离验证；目前没有同版本关闭全局 PCD 的
对照，也没有该会话的 CPU、内存、磁盘或发布队列等待采样，不能认定全局 PCD 就是唯一根因。
已经确认发生的是估计器跟踪失败，而非仅 RViz 点云显示不连续。

这些观察不能单独证明 CPU 是唯一根因，也不能证明丢失的每幅扫描都直接造成位姿误差。
此前约一倍速会话与本次会话之间还有代码和显示负载变化，不能替代同一程序、同一配置的严格对照。
没有读取真值轨迹或计算 ATE/RPE，因而不报告漂移距离或精度提升比例。

源码确认的负载与反压路径：

1. `GlobalLidarPcdMapper` 虽有独立线程，仍在同进程额外接收原始扫描、解码、去畸变、
   体素处理和写归档。只有关键帧扫描合并，不代表只有关键帧扫描才接收和解码。
2. `GlobalLidarMapDisplay::publish()` 每次遍历历史快照并排序候选；姿态高度变化可能触发
   历史点块读盘和重新着色。每批两块限制的是单次工作量，总历史显示量仍持续增长。
   `GlobalLidarMapRvizDisplay::update()` 每渲染帧遍历历史锚点更新变换。
3. 兼容整图话题 `/okvis/global_lidar_map` 有订阅者时会构建完整世界坐标点云，
   包含历史点读取、变换及着色。源码默认 RViz 的 `Global LiDAR Full Snapshot (Slow)`
   关闭，但无法从默认配置证明用户运行时没有手动打开。
4. `ThreadedSlam::publishingLoop()` 同步调用包含 PCD 状态入队的优化图回调。
   当前 `memory_bounded: true` 下，完整发布队列满 3 条时后端采用阻塞入队；
   因此发布变慢存在反压后端的通路。PCD 回调主要共享状态指针、估算队列内存并入队，
   不是同步构建整幅地图；目前没有测量证明该回调或发布队列已成为瓶颈。

独立线程和降低 nice 优先级不能证明旁路对估计器没有影响；同样，上述潜在开销也不能替代测量。

## 建议验证顺序（以最新一倍速问题为优先）

1. 同一程序、配置及一倍速，从每次全新启动开始回放相同区间，特别观察 bag 约 200–230 秒。
   A 组仅加 `global_lidar_pcd:=false`，保留其他 RViz 显示和局部建图；
   B 组开启 PCD，但关闭两个全局地图显示项；C 组开启 PCD 和增量全局地图显示，
   完整快照显示仍保持关闭。B/C 的差异用于分离全局显示负载，A/B 用于观察旁路建图开销。
   关闭模块也会关闭其 live LiDAR TF，A/B 的差异包含该模块全部附带开销，不是只隔离体素融合。
2. 对比相同传感器时间内的内点数、失跟、反馈滞后、扫描替换，以及 CPU/RSS/IO。
   如需额外关闭整个 RViz，应增加单独一组，不与关闭全局 PCD 混成唯一对照。
   `global_lidar_pcd.enabled` 在启动时读取；运行中设为 false 或只取消显示，不能当成关闭建图。
3. 如果 A 组改善而 B/C 退化，优先按实际测量结果优化旁路；如果 C 比 B 差，优先处理显示。
   如果 A 仍在相同路段失跟，再重点检查主估计器输入 QoS、扫描时间覆盖、场景退化、
   后端耗时预算和恢复逻辑。队列继续保持有界，不以无限增大队列或降低地图密度代替定位根因。
