# 激光 SLAM 的 RAM 工作集与无历史落盘模式

当前在线运行不再创建视觉 `okvis-history-*` 会话目录，也不写 `.frame` 或
`.two_pose` 文件。激光建图的队列、空间窗口和子地图保留策略始终生效。
视觉估计器的 `estimator_parameters.memory_bounded: true` 释放冷帧图像，
保留长期回环需要的特征与图观测。
可视化点云按子地图数量保留，并继续执行固定体素采样和局部空间窗口过滤。
**这不是整进程 1 GiB 硬上限；尚未通过实际长数据集的整进程内存验收。**

## 数据生命周期

| 数据 | RAM 中保留 | 默认磁盘行为 |
|---|---|---|
| 当前相机帧 | 跟踪、优化、CNN、可视化需要的图像 | 不归档 |
| 冷历史帧 | 尺寸、标定、ID、关键点、描述子、反投影、路标关联与分类结果 | 不归档；释放灰度和深度图 |
| 冻结视觉图边 | 线性化因子及恢复视觉约束需要的原始观测和路标 | 不归档 |
| IMU | 传播、预积分和异步去畸变需要的短滚动窗口 | 不归档 |
| 激光输入 | 每个在线入口保留一帧正在处理、一帧最新等待；过载替换旧等待帧 | 默认不创建 raw spool |
| 活动平面地图 | 滑动窗口内的有界体素；稳定后释放拟合样本 | 默认不落盘 |
| 已完成平面地图 | 按子地图数量管理的 RAM 缓存，保护当前参考地图 | 默认驱逐后释放；持久化 chunks 开启时才保存平面文件 |
| 可视化点云 | 最近子地图的源几何；内存取决于单张子地图的大小 | 默认不写 chunks 或 PCD |
| 轨迹、回环索引、稀疏图 | 长期位姿关系和查询索引 | 显式轨迹导出仍可用 |

释放图像只在前端安全点进行。活动 IMU/关键帧/回环窗口内的帧、外部
`shared_ptr` 持有的帧及尚在分类的帧受到保护。冷帧进入活动窗口后仍可用
驻留特征完成匹配和视觉约束恢复，但已经释放的图像不能重新加载。
重叠率和跟踪质量计算使用保留的原始图像尺寸，不依赖历史像素。

历史描述子、关键点、图观测、DBoW 索引和稀疏图仍随序列增长。取消落盘
减少磁盘 I/O 与历史图像占用，但不能据此认为剩余历史数据具有固定内存上限。

## 配置

VIO 配置（例如 `config/hilti22/okvis2-lidar.yaml`）：

```yaml
estimator_parameters:
  memory_bounded: true
  do_loop_closures: true
```

估计器已移除 `memory_archive_directory` 和 `frame_cache_mb` 参数，旧 YAML 中
这两个键不会重新开启归档。`memory_bounded: false` 保留原有全内存图像生命周期，
同样不会自动启用历史归档，但不执行冷图像释放和相应队列限制。

SE 激光配置（例如 `config/hilti22/se2-lidar.yaml`）：

```yaml
general:
  memory_archive_directory: "./okvis-history" # 仅显式开启激光持久化时使用
  max_submaps: 32 # 点云和平面缓存共用的子地图保留目标
  plane_active_max_cells: 8192
  plane_window_half_extent: 50.0
  lidar_spool_enabled: false
  pointcloud_persistent_chunks: false
  pointcloud_window_half_extent: 50.0
  mapping_queue_max_frames: 4
  state_queue_max_updates: 32
  use_point_to_plane_factors: true
  lidar_plane_only: true
  build_lidar_pointcloud_map: true
```

激光建图已移除 `general.memory_bounded`，以下策略始终生效，
旧 SE YAML 中的同名键会被忽略，即使写成 `false` 也不会关闭它们：

- `max_submaps`：点云和平面缓存共用一个保留目标，必须大于零，默认 32。
  点云保留最多 N 张有驻留点的子地图，包含活动图。
  超限优先释放最近最少写入点的旧子地图；位姿修正不会改变保留顺序。
  不再因为单张子地图超过某个 MiB 阈值而裁剪其中的点。
  平面缓存保留最多 N 张已完成图，按最近访问回收旧图。
  活动图不计入数量，当前参考图和本次查询保护的图不能被驱逐，必要时允许超出目标。
- 旧的两个独立数量键已合并为 `max_submaps`，不再读取旧键。
  旧 `pointcloud_memory_mb`、
  `plane_cache_memory_mb` 已移除，旧值不会转换成子地图数量；旧键被忽略。
- 点云体素大小、50 m 空间窗口和活动平面 cell 数量限制继续生效，
  它们是采样/空间范围策略，不是 MiB 预算。
- 建图 IMU 保留约 5 秒滚动窗口；配准点缓存清理远点并限制候选数量。
  映射包满时背压，在线状态更新队列满时明确报错，不静默替换旧更新。
  离线阻塞模式的状态输入仍使用背压。

`memory_archive_directory` 仅在显式启用 spool/chunks 时生效；默认不创建
`okvis-lidar-*` 目录。不开启持久化时，旧图被驱逐后释放；开启时先成功写盘，
之后可读取历史 chunks/平面图。磁盘 chunk 写入仍按固定点数分块，与 RAM 图数无关。
外部快照或因子的 `shared_ptr` 仍可能持有已从缓存移除的图。
**按子地图数保留不等于固定 MiB 或整进程 RSS 上限**；单张图越大，内存越多。

在线 LiDAR 按完整扫描帧缓存，不再按点数限制输入队列。ROS DDS 使用
`keep_last(1)`，异步解析线程只有一个可替换的等待帧；实时约束和建图的
RAM 输入也各保留一帧正在处理、一帧最新等待。处理跟不上时，新扫描
替换旧等待扫描，正在处理的扫描及其尚未获得相机/IMU 支持的剩余点继续
保留。逐点时间戳、强度和扫描内部顺序不变，不会只保留半帧来满足点数上限。
建图内部的 32768 点分块仅控制单次处理量，不是输入队列容量。

扫描进入处理状态时只交换缓存；新扫描的复制、被替换扫描的释放均在
输入缓存锁外完成，减少视觉线程获取 LiDAR 缓存锁时的等待。此限制约束
等待帧数，不是固定 MiB 内存上限，也不消除共享 CPU 上的计算竞争。
旧的点数容量配置和 ROS 两个队列深度
参数均已移除。离线逐点接口没有扫描边界，继续按有序点流无损输入，不能
把每个点当成一帧替换；在线调用方应使用完整扫描的批量接口。

映射包队列仍采用背压；状态和对齐更新超预算会明确报错，不能静默
丢弃历史位姿修正或约束。ROS 轨迹显示默认最多 10000 点，视觉路标显示
默认最多 100000 点，可通过 `path_max_points` 和 `landmark_max_points` 调整。

## 可选激光导出与退出

显式设置 `lidar_spool_enabled: true`
才保留建图入口收到的输入测量序列。该可选模式保留无损建图 FIFO 和固定的
32768 点磁盘读缓存，不替换建图等待扫描，可能累积磁盘积压。ROS 上游仍
使用单帧等待策略，已经在上游丢弃的扫描不会被 spool 恢复。批量接口保留
可用的点强度，但 spool 不包含完整 ROS 消息字段，不能当成原始传感器包备份。
`pointcloud_persistent_chunks: true`
才写入历史点云块和平面档案，归档目录应位于实际 SSD/eMMC，不能使用内存盘。

默认不导出 PCD。显式启用 `save_lidar_pointcloud_map` 后，RAM 模式导出当前
保留区域，持久化模式也包含历史 chunks。PCD 采用
有界外部排序、归并及全局体素去重，临时文件位于目标 PCD 文件系统。
回环更新子地图锚点，无需重写历史局部 XYZ 块。

正常退出先排空优化和位姿发布，再完成剩余可传播测量及建图。无历史落盘
模式不会额外写视觉归档。视觉估计器开启 `estimator_parameters.memory_bounded`
时跳过全历史 final BA，保留在线回环、
稀疏图求解和轨迹输出。已有磁盘历史文件不会自动删除，也没有进程重启续跑入口。

## 验证与限制

RAM 模式组件回归覆盖：冷灰度/深度图释放、外部共享引用固定、活动帧保护、
历史描述子和反投影保留、图像释放前后重叠率一致，以及无文件/目录创建。
旧显式归档库接口仍保留供兼容与独立测试使用，在线 `ThreadedSlam` 不调用它们。

此前点云导出压力测试和无输入启动内存测量属于旧分页版本，不能证明本轮
RAM-only 历史模式的运行峰值。最终验收需要长数据集持续测量 RSS/PSS、
回环及退出峰值，并比较 ATE/RPE、回环召回、有效激光因子和处理时延。
神经网络分支需要在启用 NN 的环境单独验证。
