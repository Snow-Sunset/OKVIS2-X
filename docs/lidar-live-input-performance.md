# 实时 LiDAR 等待扫描替换的性能优化

`Realtime LiDAR input replaced ... old waiting scan` 来自估计器的实时配准输入缓存。
它与 ROS DDS、订阅解码线程以及建图输入的替换统计不同，不能单独用它判断解码慢。
实时缓存继续保留一个活动扫描和一个最新等待扫描，活动扫描的未消费尾部不会被替换。

## 消费时机

独立视觉前端原来只按关键候选请求提交后端处理。默认候选最大间隔为 0.25 秒传感器
时间；若扫描周期为 0.1 秒，后端空闲时也可能在两次图像处理之间替换等待扫描。
三倍回放会进一步缩短墙钟上的到达间隔。

现在，满足以下条件时，可额外提交普通图像更新：跟踪有效、有完整扫描的末点严格早于
当前图像、后端空闲且无等待或活动任务。该更新不强制关键帧，不更新视觉候选门限的
起点。视觉候选和这类额外更新都只在后端空闲时接纳；同一时刻最多一个已接纳任务，
不在活动优化后面积压旧图像。忙碌时当前候选保持未接纳，后续新图像重新提议。
已接纳任务完成处理，不通过替换或删除已接纳任务来追赶输入。
整段早于反馈传播锚点的迟到扫描不触发额外图像更新，避免执行没有新增激光因子的
优化；此类输入需要结合时间参考和原有消费路径单独诊断。

## 每次处理的计算开销

- 去畸变沿用原有 IMU 时间游标与插值积分。固定偏置时，跳过只服务于偏置增量校正的
  Jacobian 和旋转矩阵积分；建图的批量位姿查询也使用该路径。默认传播接口仍保留
  偏置校正；固定偏置模式严格拒绝偏置变化。
- 点面预筛选通过 `PlaneMap::hasMatch()` 判断是否存在合格邻域平面，首次成功即可返回。
  门限与 `match()` 共用同一实现；构造实际图因子时仍选择最佳平面。
- 初始候选和最大候选共用一次空间哈希优先级选择。弱重叠需要扩容时，只查询新增
  候选，保留原始点序，不复制完整候选云再重新筛选。
- 在默认初始 4096、最大 8192 的情况下，扩容路径的预筛选查询数由 12288 降为 8192。
  这是调用次数变化，未进行运行耗时测量。无须扩容时仍只查询初始集合。
- 最终只保留少量因子时使用部分 Fisher–Yates 抽样，保持均匀且无放回；交换次数与
  保留因子数成正比，不再打乱所有已匹配候选。
- ROS 解码后先提交实时估计器，再提交建图，减少建图提交开销对配准输入的直接阻塞。
  两个分支维持各自 FIFO、水位与独立异常处理。
