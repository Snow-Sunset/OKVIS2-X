# 异步关键帧回环检索

视觉跟踪不再逐帧调用 DBoW 查询。最终判定为关键帧且初始化完成后，前端向独立
place-recognition 线程提交请求。关闭 `do_loop_closures` 且没有加载其他组件时，不启动该线程。

## 线程边界

- 请求只携带独立复制的关键点、描述子、相机外参，以及已完成历史帧的局部三维点。
  不携带原始图像，也不向后台传递 `Estimator` 或可修改的实时帧。
- 历史三维点在帧转换为 pose-graph 帧后复制一次，保持在该历史传感器坐标系中。
- 后台独占 DBoW 查询、过滤和数据库插入，执行描述子匹配、RANSAC 和独立 Ceres
  位姿细化，返回经过几何验证的候选。查询先于插入，避免自匹配。
- 多组件地点识别也使用后台查询和独立快照；组件必须在开始处理关键帧前加载。
- 估计器所有者在已等待局部优化完成的安全点，重新检查候选是否仍可用。
  由于查询帧与当前帧通常不同，针对当前帧重新几何验证，再调用原有
  `attemptLoopClosure`、恢复观测及地图匹配路径。旧查询的相对位姿和信息矩阵
  不会被直接套用到新的图端点。全部图修改仍由估计器所有者串行执行。
  不再可用的历史候选会被禁用，重新完成并解除最近闭环保护后才刷新；请求序号
  防止排队中的旧快照错误地重新启用已失效的候选。

本阶段移走了持续增长的逐帧历史检索和候选初验；真正闭环时的当前帧复验和图更新
仍可能造成短时开销。它不是完整的前后端解耦，也不保证加速回放完全不丢图像。

## 队列与生命周期

请求队列最多等待 4 张关键帧，满时跳过尚未接纳的可选检索，不阻塞图像处理。
结果最多保留 8 个尚未应用的提案；过载时更新旧提案，不涉及删除已经接受的图约束。
正常退出排空已接纳检索请求并结束工作线程，然后在估计器允许时处理结果。
重置先停止线程，再清空旧请求、提案和数据库，防止旧帧 ID 污染新运行。
后台异常通过结果获取、统计读取或后续提交传播给调用者。

历史视觉数据库和三维特征快照仍随已接纳关键帧增长；队列有界不代表历史内存固定。

## 观测与验证

`Place recognition worker` 日志输出 submitted、processed、skipped、pending、verified，
以及查询/几何验证的最大耗时（毫秒）。后台使用独立时钟统计，避免并发更新旧的
全局 Timer 累加器。前端原有 `2.03 loop closure query` 不再增长；实际应用提案时的
当前帧复验记为 `2.11 revalidate loop proposal`。

`okvis_async_place_recognition` 回归覆盖：稀疏 DBoW ID、独立快照、避免自匹配、
真实几何重访、描述子相同但几何不一致的拒绝、候选禁用与恢复、有界请求队列、
正常退出及清空后重启。

```bash
ctest --test-dir <build-dir> -R '^okvis_async_place_recognition$' --output-on-failure
```

实际性能需要在相同数据段、相同回放倍率下比较图像替换次数、前端 P95/P99、
后台积压、闭环成功次数和轨迹误差，不能仅凭线程拆分判断实时性或精度改善。
